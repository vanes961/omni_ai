# Roadmap

## Принципы

- UI обращается к сценариям приложения, а не напрямую к AI-провайдерам, Telegram API или scheduler.
- Межмодульные зависимости задаются интерфейсами и покрываются тестами с fake-реализациями.
- Секреты и пользовательские данные не сохраняются в `shared_preferences`.

## 1. `ai_engine`

Статус: запланирован.

- Определить нейтральные модели запроса, ответа и ошибки.
- Добавить интерфейс движка с поддержкой асинхронного выполнения, отмены и тайм-аута.
- Изолировать адаптер конкретного AI-провайдера от UI и `system_core`.
- Покрыть сценарии успеха, ошибки, отмены и недоступности провайдера fake-движком.

Критерий готовности: System Core может запустить задачу через интерфейс движка, отобразить её состояние и записать события в `run_history` без зависимости UI от SDK провайдера.

## 2. `telegram_bot`

Статус: запланирован.

- Реализовать отдельный адаптер Telegram, который вызывает сценарии приложения через интерфейсы.
- Согласовать набор команд и способ получения обновлений: webhook или long polling.
- Ограничить команды allow-list пользователей и добавить защиту от повторной обработки обновлений.
- Хранить токен бота только в переменных окружения или серверном secret store.
- Тестировать разбор команд и ответы без реального Telegram API.

Критерий готовности: авторизованный пользователь может запросить статус, запустить задачу и получить результат; неавторизованные команды не запускают процессы.

## 3. `scheduler_core`

Статус: запланирован.

- Определить модель задания: расписание, следующий запуск, статус, политика повтора и идентификатор процесса.
- Добавить создание, паузу, отмену и повтор задания через отдельный сервис.
- Сохранять задания и состояние выполнения так, чтобы переживать перезапуск приложения.
- Передавать запуски в сценарии процесса и связывать их с записями `run_history`.
- Выбрать стратегию фонового выполнения отдельно для Web и Desktop: ограничения платформ различаются.

Критерий готовности: запланированная задача запускается по расписанию, соблюдает retry/backoff, а её исход виден в истории.

## Порядок реализации

1. `ai_engine`: сначала стабилизировать сценарий выполнения и его контракт.
2. `telegram_bot`: подключить внешний транспорт к готовым сценариям и добавить авторизацию.
3. `scheduler_core`: переиспользовать сценарий запуска и постоянное хранение; до фоновых задач согласовать целевые платформы.
